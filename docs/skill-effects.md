# Accepted skill and buff integration

The accepted XDT contains 277 unique positive skill IDs across 31 skill types. Identical repeated rows are deduplicated by identity; conflicting rows fail loading. `tools/audit_skill_effect_coverage.py` regenerates [the full identity and consumer matrix](skill-effect-coverage.json), preserving costs, cooldowns, durations, targets and source consumers. The matrix classifies every accepted type explicitly and raises on a newly unclassified type. Its statuses are static contract coverage, not a claim of full Unity player acceptance.

Source evidence is the local `../OpenFusion` checkout (`Abilities.cpp/.hpp`, `Buffs.cpp`, `PlayerManager.cpp`, `Items.cpp`, `Missions.cpp`, `Racing.cpp`, `MobAI.cpp`) and bounded CLR IL inspection of `../builds/retrobution-20260821/main.unity3d`, SHA256 `01b544976b2d54355507cf30fe6dfada2b476b92b209a3d47c1499669ed9b4ef`, assembly `Assembly - CSharp.dll`. The inspected original `Status.UpdateSkillBuff(sP_FE2CL_PC_BUFF_UPDATE)` token `0x06000b56` confirms absolute source-value addition for run and jump, snare subtraction, and vehicle speed max before subtraction. `CnGuiSkillBuffIcon.UpdateIconList` resolves `m_iBuffIcon` through the skill icon table. `GameFrame.SkillResultDistributor` token `0x0600080a`, IL_0330, has a 35-entry native result switch. Bounded raw inspect outputs are retained below `../FusionForge/target/buff-status-native.json` and `buff-distributor-native.json`; these are CLR evidence, not recovered original source.

Implemented integration repairs:

- Effective buff queries exclude expired stacks immediately. Expiry is processed before periodic effects; expiration of a stronger stack sends Change with the surviving weaker value. Nano, group, egg, item and environment sources remain separate.
- Passive Nano auras reconcile their actual source identities each server tick. Numeric target type 3 is group membership in local OpenFusion; type 2 self powers are not spread to the group. Same-instance membership, active Nano stamina, death, deactivation and boost changes affect reconciliation. Ordinary active GroupNano casts are retained. A dead holder retains its valid self Phoenix until consumed. This reconciler currently covers player group recipients; native group-NPC aura ownership still needs coordinated integration with NPC passive handlers.
- RewardCash and RewardBlob multiply the existing combat/mission/racing reward rates by local OpenFusion's 1.20, or 1.23 with an active boosted Nano. Eggs retain their existing rate. This deliberately follows the accepted local server formula rather than inferring percentages from XDT A values.
- Phoenix regen3 and group regen4 replace server TODO crashes. Self Phoenix requires a dead holder and its active Nano, drains only that Nano and preserves other carried stamina. A real PhoenixGroup cast grants a ten-second one-shot authorization for regen4; this bounded authorization is a server validation extension. Replaying regen4 or requesting it without a real cast fails. Both restore half maximum HP at the current location.
- Leech type30 now emits local OpenFusion's 36-byte Heal16 + Damage20 trailer, with actual capped caster healing, caster identity and target post-damage HP. It previously emitted a 20-byte Damage trailer while declaring type30.
- Player Sleep is removed when damage lands. Native run/snare/immobilization values affect server speed and Unity walking/vehicle motion. Unity jump adds the source centiunit value to the accepted 5.68 launch velocity while on foot.
- Unity decodes exact PC_BUFF_UPDATE44, timeout12 and typed time-tick trailers. Local and replica conditions survive Nano/NPC effects, interest entry and timeout. Infection ticks update HP, Nano stamina and deactivation, including the protected negative damage sentinel. Stamina6/7 and battery-drain21 post-states are decoded with their actual trailer widths.
- Accepted subtype3 gumballs now use their actual linked skill144/191/197 and flavor metadata, including wildcard flavor4. Subtype4 healing and known timed effects use their linked IDs, one-item consumption, CashItem source and authored cooldown. This is an explicit server continuation beyond local OpenFusion's gumball-only dispatcher. Unsupported capacity/token/Nanocom contracts are rejected before consumption. Both item-use success and broadcasts carry their required typed trailers, and Unity inventory context actions update from server receipts.
- The gameplay buff display resolves the original XDT buff icon identity and shows server timer durations. A display deadline cannot invent a server removal. Phoenix UI sends native regen3/4; crowd control gates movement and combat input.

The four `item::buff_item_tests` regressions drive production item-use handlers over all13 accepted subtype4 supported item IDs, the three wildcard gumballs, cooldown/replay and flavor rejection preservation, exact linked skill IDs and complete observer trailers. Unsupported contracts are checked for rejection without consumption.

The seven `skills::buff_tests` regressions exercise effective-stack lifetime, source-owned aura removal, reward-rate composition and egg exclusion, Phoenix authorization/stamina preservation and the exact Leech result. `BuffEffectsTests` exercises packet widths/offsets, malformed packet rejection, condition timeout, periodic infection state, Leech target identities, native speed math and Phoenix request IDs.
